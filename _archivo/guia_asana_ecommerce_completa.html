Módulo 01

Introducción a Asana

¿Qué es Asana?

Asana es una plataforma de gestión de trabajo en equipo que permite organizar proyectos, asignar responsabilidades, hacer seguimiento del progreso y colaborar de forma asíncrona. Es usada por equipos de software en empresas como Airbnb, Dropbox y Spotify.

Para nuestro proyecto ShopFlow, Asana será el centro de comando donde el equipo de desarrollo coordinará cada sprint, tarea y entregable del e-commerce.

1

Crear tu cuenta y configurar el perfil

El primer paso es tener tu espacio personal en Asana correctamente configurado.

Pasos a seguir

  1. Ve a asana.com → clic en "Empezar gratis" → ingresa tu correo y contraseña segura.
  2. Abre el correo de verificación y confirma tu cuenta.
  3. En el menú superior derecho → tu avatar → "Configuración del perfil".
  4. Completa: nombre completo, foto de perfil y zona horaria (América/La_Paz).
  5. En "Notificaciones" activa: resumen diario por correo + notificaciones en la app.
2

Crear el Workspace "ShopFlow Dev"

El workspace es el contenedor raíz de todo tu trabajo. Todos los proyectos y equipos viven dentro de él.

Pasos a seguir

  1. Clic en el logo de Asana (arriba a la izquierda) → "Crear nuevo workspace".
  2. Nombre: ShopFlow Dev | Tipo de uso: Trabajo / Desarrollo de software.
  3. Invita al equipo: ingresa los correos de Frontend Dev, Backend Dev, QA y Product Owner.
  4. Crea 3 equipos dentro del workspace: Frontend, Backend API y QA & Deploy.
💡

Tip: Si practicas solo, crea 2–3 cuentas con diferentes correos (puedes usar gmail+alias@gmail.com) para simular un equipo real y practicar la colaboración.

8

Crear campos personalizados

Los campos personalizados permiten añadir información específica a todas las tareas del proyecto:

Cómo crearlos

  1. En el proyecto → clic en ⚙️ "Personalizar" (esquina superior derecha).
  2. Agrega campo "Prioridad" → tipo Lista → opciones: Alta 🔴, Media 🟡, Baja 🟢.
  3. Agrega campo "Sprint" → tipo Lista → opciones: Sprint-1, Sprint-2, Sprint-3, Sprint-4.
  4. Agrega campo "Módulo" → tipo Texto → para escribir: Auth, Catálogo, Carrito, etc.
  5. Agrega campo "Estimación (días)" → tipo Número → para asignar esfuerzo en días.
9

Usar la vista de línea de tiempo (Gantt)

La vista Timeline te permite ver la planificación global y detectar cuellos de botella:

Cómo usarla

  1. En la barra de vistas del proyecto → clic en "Línea de tiempo".
  2. Arrastra las barras para ajustar fechas de inicio y fin.
  3. Conecta tareas dependientes arrastrando desde el borde de una barra hacia la otra.
  4. Verifica que ningún miembro tenga tareas solapadas en la misma semana.
  5. Comparte con stakeholders: clic en "Compartir" → enlace de solo lectura.

11

Crear subtareas para trabajos complejos

Las subtareas permiten desglosar una tarea grande en pasos concretos y asignarlos a personas diferentes:

Subtareas de "Checkout completo"

  • Formulario de datos de envío con validaciones (María A. — 1 día).
  • Resumen de pedido con desglose de precios (María A. — 0.5 días).
  • Integración frontend con API de pagos Stripe (María A. — 1 día).
  • Endpoint POST /orders en backend (Luis R. — 2 días).
  • Email de confirmación de pedido automático (Luis R. — 1 día).
  • Testing del flujo completo de compra (Carlos P. — 1 día).
💡

Regla de oro: si una tarea toma más de 3 días, es señal de que debe dividirse en subtareas más pequeñas. Las tareas pequeñas son más fáciles de estimar, asignar y completar.

12

Establecer dependencias entre tareas

Las dependencias evitan que alguien empiece a trabajar en algo para lo que no están listos los prerequisitos.

Cómo establecerlas

  1. Abre la tarea dependiente (ej: "Página de listado de productos").
  2. En el panel derecho → busca "Dependencias" → "Marcada como dependiente de..."
  3. Busca y selecciona: "API REST GET /products".
  4. Repite para cada par: Testing → Login completo; Checkout → API de pagos.

Módulo 06

Organizar tu trabajo personal

16

Usar "Mis tareas" como tu centro de control diario

"Mis tareas" es la vista personal donde ves todo lo que está asignado a ti, organizado por prioridad y fecha.

Rutina diaria recomendada (10 min al inicio del día)

  1. Abre "Mis tareas" desde la barra lateral.
  2. Ordena por Fecha límite → identifica las tareas más urgentes.
  3. Asigna las 3 tareas más importantes a "Hoy" en la sección de prioridad.
  4. Mueve las que no harás hoy a "Próximamente" o "Más tarde".
  5. Al finalizar cada tarea → márcala como completada con el círculo ✓ o Tab+C.
17

Crear tareas personales y recordatorios

Además de las tareas del proyecto, puedes crear tareas personales solo visibles para ti:

Ejemplos de uso

  • Recordatorio: "Revisar PR de María antes de las 16:00".
  • Seguimiento: "Confirmar credenciales de Stripe con el PM".
  • Aprendizaje: "Ver tutorial de Asana Timeline – Viernes".
  • Nota: "Pendiente documentar la API de productos al final del sprint".
💡

Las tareas creadas directamente en "Mis tareas" sin asignarlas a un proyecto son privadas. Nadie más del equipo las verá. Úsalas como tu bloc de notas de acción.

18

Configurar el panel de inicio personalizado

El Home de Asana puede configurarse para mostrar exactamente lo que necesitas ver cada día:

Widgets a activar

  • Mis tareas: las 5 tareas más urgentes de hoy.
  • Proyectos recientes: acceso rápido al MVP ShopFlow.
  • Colaboradores: ver en qué están trabajando tus compañeros.
  • Reuniones: próximos standups o demos del sprint.

Módulo 07

Colaborar con tu equipo

19

Comunicación asíncrona dentro de Asana

El objetivo es que toda la comunicación del proyecto ocurra dentro de Asana, no en WhatsApp o correos dispersos.

Buenas prácticas

  • Usa @nombre en comentarios para notificar a alguien específico: "@Luis, la API necesita manejar paginación, ¿puedes agregarla al endpoint?"
  • Escribe actualizaciones de avance diario en el comentario de la tarea activa.
  • Si hay un bloqueante, documéntalo en el comentario y menciona a quien puede desbloquearlo.
  • Usa el 👍 en comentarios para confirmar que leíste la actualización.
  • Adjunta capturas de pantalla, maquetas de Figma o enlaces de PR de GitHub directamente en la tarea.
20

Retrospectiva del sprint en Asana

Al finalizar cada sprint, documenta aprendizajes directamente en el proyecto:

Proceso de retrospectiva

  1. Crea una sección nueva: "Retrospectivas" en el proyecto.
  2. Crea tarea: "Retro Sprint 1 – [Fecha]".
  3. En la descripción usa esta plantilla:
    ✅ ¿Qué salió bien?
    ⚠️ ¿Qué mejorar?
    🚧 ¿Qué nos bloqueó?
    🎯 Acciones para el Sprint 2:
  4. Crea subtareas con las acciones de mejora, asignadas a responsables con fecha límite.

📎 Entregables para la evaluación

Para ser evaluado/a, debes entregar: (1) enlace de solo lectura al workspace de Asana con el proyecto completo, (2) carpeta con capturas de pantalla de cada módulo practicado (mínimo 10 capturas), y (3) documento PDF con reflexión de 1 párrafo por módulo indicando qué aprendiste y qué aplicarías en un proyecto real.

⚠️ Condiciones de evaluación

El proyecto debe mostrar actividad real (tareas movidas, comentarios escritos, fechas asignadas). Un proyecto con tareas vacías o sin interacción del equipo no será evaluado como completo aunque tenga la estructura correcta. La calidad de los comentarios y descripciones cuenta tanto como la cantidad.
